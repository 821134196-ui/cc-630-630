# 企业会议纪要保密级别与定向分发系统

会议纪要按**密级**和**指定名单**定向分发。收到提醒邮件 ≠ 拥有持续访问权：
员工**每次打开链接**都按**当前岗位与授权**实时核验，转岗或授权撤回后旧链接**立即失效**。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Java 17、Quarkus 3.15、Hibernate ORM + Panache |
| 前端 | Svelte 4 + Vite（构建产物由 Quarkus 同源提供） |
| 数据库 | SQLite（文件位于 `data/minutes.db`） |
| 附件 | 本地存储 `data/attachments/`（随机文件名，仅受控接口可读） |
| 邮件 | 模拟实现，落库到「邮件外发箱」页面，**只发提醒链接，不附正文** |

## 一条命令启动

```bash
./run.sh
```

首次运行会自动 `npm install`、构建前端并启动 Quarkus。
启动后打开 <http://localhost:8080>。

前置条件：JDK 17+、Maven 3.9+、Node 18+。

## 演示账号

| 用户名 | 角色 | 说明 |
|---|---|---|
| `recorder` | 记录员 | 起草/修订纪要，上传正文+附件、标注密级、提议接收名单 |
| `approver` | 负责人 | 预览最终分发对象、批准/驳回、事后撤回授权 |
| `admin` | 管理员 | 员工转岗、密级资质调整 |
| `zhang` | 员工 | 研发部高级工程师，密级资质 3 级 |

| `liu` | 员工 | 资质 4 级 |

## 核心安全设计

1. **正文与附件同一版本**：创建/修订在同一个 multipart 请求、同一个事务、同一个
   `MinutesVersion` 中写入；不允许只更新正文或只更新附件。修订产生新版本，旧版本
   在新版本获批前继续有效，获批后整体切换。
2. **每次请求实时核验**（`AccessService`）：打开正文、下载附件都实时检查
   纪要已发布 → 授权行 active → 员工当前部门/岗位与授权时一致 → 当前密级资质达标 →
   链接令牌与本人绑定。不依赖令牌过期，不做任何缓存。
3. **转岗即失效**：管理员调整岗位/资质后，相关授权行立即作废（`TRANSFERRED` /
   `CLEARANCE_DOWNGRADE`），旧链接下一次打开即 403；**历史授权行与分发记录永久保留**。
4. **审批撤回即失效**：负责人从名单移除或单独撤回，授权行置为
   `REMOVED_BY_APPROVER`，旧链接立即 403。
5. **附件无法绕过正文读取**：物理文件放在非静态目录、随机文件名；下载端点执行与
   正文相同的实时核验，且附件必须属于**当前发布版本**，旧版本附件通过新链接访问被拒绝。
6. **邮件不含敏感内容**：模拟邮件只含标题、密级标识和链接，正文/附件内容从不进入邮件；
   「邮件外发箱」页面可逐封检查。
7. **全量审计**：成功/失败的查看、下载（含拒绝原因）、审批、撤回、转岗全部记录。

## 推荐验证路径（与自动化测试对应）

1. `recorder` 新建机密纪要（正文 + 至少一个附件），提议 `zhang`，提交审批。
2. `approver` 在审批页预览最终名单与草稿内容，仅保留 `zhang` 后批准。
3. `zhang` 打开列表中的链接可见正文、可下载附件；直接把链接给 `liu` 打开 → 被拒。
4. `admin` 将 `zhang` 转岗到市场部 → 刷新旧链接，正文与附件下载**立即 403**；
   在审批详情页确认历史分发记录仍在。
5. 调回后 `recorder` 修订 v2（新正文+新附件）并重新审批发布；
   用 v2 链接访问 v1 旧附件 → 403（版本一致性）。
6. `approver` 撤回 `zhang` → 旧链接立即 403。
7. 「审计 / 邮件外发箱」页面查看拒绝事件，并确认邮件正文不含敏感内容。

## 自动化测试

```bash
mvn test
```

`SecurityFlowTest` 覆盖：正常访问、转岗阻断旧链接、审批撤回阻断旧链接、
正文/附件版本一致性、越权与伪造令牌下载拒绝、邮件无正文泄漏、审计留痕。

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/minutes` (multipart) | 创建：title/classification/body/files 同一版本 |
| PUT | `/api/minutes/{id}/revise` (multipart) | 修订，生成新版本 |
| POST | `/api/minutes/{id}/submit` | 提交候选名单审批 |
| GET | `/api/minutes/{id}/approval-preview` | 审批人预览最终分发对象 |
| POST | `/api/minutes/{id}/approve` | 批准最终名单并发布、发提醒 |
| DELETE | `/api/minutes/{id}/recipients/{username}` | 撤回授权（旧链接立即失效） |
| POST | `/api/minutes/{id}/recipients/{username}` | 向已发布纪要追加/恢复接收人（调回场景，补发提醒） |
| GET | `/api/view/{id}?t=token` | 员工打开链接（**实时核验**） |
| GET | `/api/attachments/{id}/download?t=token` | 附件下载（**同样实时核验**） |
| PUT | `/api/employees/{username}/transfer` | 转岗/资质调整 |
| GET | `/api/monitor/audit` · `/emails` | 审计日志、模拟邮件外发箱 |

> 演示系统用 `X-Username` 请求头识别身份（无密码），便于演示；生产环境应替换为
> 真实会话/OAuth——所有授权逻辑都在服务端实时计算，与认证方式无关。
