# 企业会议纪要保密级别与定向分发系统

会议纪要按**密级**与**指定名单**定向分发。核心安全原则：**收到提醒邮件 ≠ 拥有持续访问权**。
员工每一次打开链接、下载附件，系统都按其**当前岗位密级 + 授权状态 + 审批状态**实时核验；
转岗、授权撤销、负责人撤回审批后，旧链接立即失效，历史分发记录永久保留。

技术栈：**Java 21 · Quarkus 3 · Hibernate ORM · SQLite · Svelte 4（Vite）**；附件本地存储，邮件接口模拟落盘；`./run.sh` 一条命令启动。

## 业务流程与安全设计

1. **记录员起草**：上传正文与附件、标注密级（公开/内部/秘密/机密），选择建议接收人。
   编辑页顶部有醒目的彩色密级横幅。
2. **原子版本**：一次修订中，**正文与全部附件作为同一个版本**在单请求、单事务内发布，
   不存在“只改正文”或“只换附件”的半成品版本；空正文拒绝提交。
3. **负责人审批**：预览页实时显示**最终分发对象**，可在建议名单上增删；
   密级不足的人员被标红且无法加入最终名单（服务端二次强校验）。
4. **定向分发**：审批通过时冻结接收人名单快照，为每人生成专属 token 授权，
   发送**仅含提醒语和专属链接、绝不含正文**的模拟邮件（落库 + `backend/data/mail/` 落盘）。
5. **员工访问**：点自己链接打开，每次都实时核验；附件下载走同一鉴权入口。
6. **权限终止（旧链接立即失效，记录保留）**：
   - 员工**转岗**（岗位/密级变化）；
   - 管理员**撤销个人授权**；
   - 负责人**撤回审批**（版本置 WITHDRAWN）；
   - 发布新版后旧版（SUPERSEDED）。

### 每次访问实时核验项（`AccessControlService`）

token 有效 → 当前登录人是授权本人（防转发）→ 授权未撤销 → 版本为 APPROVED
→ 本人在审批名单快照内 → **当前**岗位密级 ≥ 版本密级 → 账号启用。
附件下载额外校验附件必须属于当前授权版本（防拿 A 链接读 B 文件）。

### 关键实现点

- 附件存放于 `backend/data/files/`，**无任何静态资源映射**；读取只能走
  `/api/access/attachment/{token}/{attachmentId}`，无法绕过正文页面直接读文件。
- 访问**拒绝也写审计**：审计在独立短事务提交，不随后续拒绝异常回滚（放行/拒绝均留痕）。
- 邮件内容有后端自检字段 `containsBody`，若包含版本正文会在管理页标红告警。
- SQLite 单连接写池（`quarkus.datasource.jdbc.max-size=1`），契合其单写者模型。

## 目录结构

```
backend/
  src/main/java/com/secmin/
    domain/     实体：AppUser/Minutes/MinutesVersion/Attachment/DistributionGrant/AccessAudit/SimulatedMail…
    service/    AccessControlService（实时鉴权）、MinutesService（版本/审批/转岗/撤销）、
                AuditService（独立事务审计）、FileStorageService（本地附件）、MailService（模拟邮件）
    web/        REST 资源（纪要/审批/访问入口/管理）、当前用户、异常映射
  src/test/java SecurityFlowTest（安全场景集成测试）
frontend/
  src/pages/    登录、纪要列表/编辑（密级横幅+原子提交）、审批中心/最终名单预览、
                我的链接、链接查看（拒绝页+鉴权下载）、管理审计台
  src/api.js    fetch 封装、带身份头的附件下载
run.sh          一键构建并启动
```

> 说明：本系统为演示用途，登录身份通过 `X-Account` 请求头切换（前端“登录”即选择账号）。
> 生产环境应替换为真实会话/JWT；但所有数据访问与下载的权限判定均在服务端完成，不依赖前端传入的身份以外的任何参数。
